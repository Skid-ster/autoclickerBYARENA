MacroClicker v1.10.0 makes long-interval clicking idle-cheap, turns every
remaining silent click-worker failure into a visible and recoverable state,
and removes the last blank status line.

## Highlights

- **Idle CPU at long intervals.** Waits that are longer than the precision
  window now park on a dedicated stop event in slices of at most 250 ms and
  QPC-spin only the final 12 ms before a dispatch. Fast clicking keeps the
  pure spin schedule it has always had; a 10-minute interval no longer holds
  a logical CPU at 100 %, which is itself a timing risk through heat,
  throttling and battery drain.
- **Stop lands at any interval.** Every stop path — Stop, the start/stop
  hotkey, F8, the repeat limit, a window close — signals that stop event, so
  a worker parked inside an hour-long wait leaves the wait instead of
  finishing the interval.
- **A lost worker heals itself.** The watchdog replaces a worker that is
  gone, up to 8 replacements per run, and reports it once in recovery
  wording (`The click worker stopped; it was restarted, …`) rather than
  asking you to restart the app. Past that budget the status says the worker
  can no longer be restarted, which is the honest outcome for a process that
  keeps losing it.
- **Lateness is admitted, not hidden.** The worker publishes the dispatch it
  currently owes. If it falls more than 2 s behind, the status strip raises a
  single non-repeating warning that names the delay, and it clears back to
  the exact running line once the dispatch lands. A worker blocked inside a
  Windows input call cannot be interrupted, so it is observed rather than
  reported as healthy.

## Added

- Idle-cheap scheduling for long intervals, as described above, with the spin
  tail and park slice sizes chosen so no click is dispatched later than it
  was before.
- Self-healing for a lost click worker, bounded at 8 replacements per run.
- Visible lateness reporting for a dispatch the worker owes and has missed.
- A status line that is never blank. When idle it states exactly what Start
  will do, following the button, click type, coordinate mode, repeat limit
  and interval: `Ready — left single click at the cursor, 10.00 CPS.` or
  `Ready — left single click at -12, 640 ×500, every 5:00.000.`
- Live session counters in the status strip's reserved row: delivered clicks
  (and the repeat budget when one is set) or elapsed time, bounded to a short
  line, with a hover tooltip that also reveals any elided status text.

## Changed

- A panic inside the click loop is contained and reported as an error status
  with the session ending cleanly, instead of the worker thread dying while
  the interface keeps showing a session that is not running. The release
  profile is built with `panic = "unwind"` so the containment ships in the
  executable.
- The stop event is cleared before each new session, so a stop signal from a
  previous session can never end the next one early.

## Fixed

- Stop, the start/stop hotkey, F8, the repeat limit and window close now
  interrupt a long wait instead of waiting for the next scheduled click.
- A lost worker no longer leaves the dashboard showing a running session with
  no way to recover short of restarting the app.
- The empty status area before the first action no longer reads as a blank
  strip with no indication of what the current settings will do.
- Removed the three unused dashboard chart colors; every remaining theme
  entry is referenced by the paint path.

## Safety and limitations

- The spin schedule is unchanged for fast clicking. A wait only parks when
  the part before the spin tail is longer than the smallest park worth
  handing to the OS, so no dispatch is later than it would have been before.
- Parking uses a Windows manual-reset event (`WaitForSingleObject`), not
  `std::thread::sleep`. The wake was exercised against a simulated event
  during development; the wake latency of `WaitForSingleObject` on any
  particular Windows machine was not measured, so no timing figure is
  claimed for it.
- A worker blocked inside a Windows input call cannot be interrupted by any
  means available to this process. It is observed and reported, never killed.
- Self-healing is bounded on purpose. It is a recovery for a lost thread, not
  a reason to keep using a session whose worker keeps dying.
- Clicking still sends real input, including to other applications. Test on a
  safe, disposable target.

## Compatibility

- Windows 10 21H2 or later and Windows 11, x64.
- Existing settings remain in `%APPDATA%\op-auto-clicker\settings.conf`;
  saved click settings, themes, appearance and window-scaling preferences are
  retained, and no migration is required.
- Update installation is always initiated by you. A recognized source
  checkout requires Git, a clean `main` branch and the expected GitHub
  origin.
- The executable is unsigned, so Windows SmartScreen may request confirmation
  on first launch.
