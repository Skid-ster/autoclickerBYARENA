MacroClicker v1.5.0 makes software updates consistent across portable and source installations, clarifies every stage of the in-app updater, and formalizes the project's public documentation and release process.

## Highlights

- The footer **Update vX.Y.Z** action can now start the complete verified update and restart sequence directly.
- Recognized source checkouts are updated in place instead of being sent to a manual browser download.
- Release assets now include a standalone `SHA256SUMS.txt` verification file.

## Added

- Source-checkout update support for Cargo builds running from a recognized MacroClicker repository. The updater requires a clean `main` branch and the expected GitHub origin, fast-forwards to the exact release tag, verifies the crate version, then installs the release build after exact size and SHA-256 verification.
- Installation type and published download size in the Updates window.
- A shape-coded update path showing the source/download/verification/install/restart stages.
- Contributor, security, release-process, changelog, issue-template, and pull-request documentation.
- MIT License at the repository root.

## Changed

- The one-click updater now uses a shared installation classification across the footer and Updates window, so the action offered in both places is the same.
- GitHub releases are published from checked-in release notes. CI appends the exact size and SHA-256 of the binary being published.

## Fixed

- Source builds inside the project checkout no longer fall back to the browser solely because their executable lives under Cargo's `target` directory.
- Cancellation and failure states now distinguish an unchanged running program from a source checkout that was already fast-forwarded.

## Compatibility

- Windows 10 21H2 or later and Windows 11, x64.
- Existing settings in `%APPDATA%\op-auto-clicker\settings.conf` are preserved.
- Portable v1.4.1 installations can update through the in-app updater. Source builds using v1.4.1 or earlier must move to v1.5.0 once through Git/Cargo or the portable release; later source-checkout updates use the new in-app path.
- The executable remains unsigned, so Windows SmartScreen may request confirmation on first launch.
